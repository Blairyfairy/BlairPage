What these percentages mean

Each score is the estimated ATS potential of a resume that could be created from index.html for that job title.

Featured — 95% to 100% tailored-resume ATS potential

    Example: “L3 Linux Managed Applications Support Engineer — 100%” means: if Blair builds an L3-focused resume from the Liquid Web / Nexcess managed applications material already on index.html, that resume can align essentially fully with typical ATS keyword sets for that title. Featured cards and table rows mark the full 95–100% band.

    Strongest tailored-resume families (95–100%):
    • L3 / managed hosting — densest production bullets (Liquid Web, Nexcess).
    • Linux / RHCE — 20y servers + RHCE6 support a near-complete Linux admin resume.
    • MySQL / Percona HA — PXC/Galera/XtraBackup/PMM form a DBA-ready cut.
    • WP / Woo / Magento hosting — multi-year e-comm full-stack material.
    • AWS / OpenStack hybrid ops — certs + hybrid cloud title support high cloud scores.
    Scoring rules:
    • Source = facts on index.html only (no invented experience).
    • Score = estimated ATS potential of a targeted resume cut for that title.
    • No artificial ceiling — densest families can reach 95–100%.
    • Dense exclusive bullets raise scores; thin/adjacent families score lower.
    • Gaps (K8s lead years, Azure/GCP primary) still reduce potential for those titles.
    Not measuring:
    • How the live multi-role portfolio page ranks in one generic ATS pass
    • Interview probability or offer rates
    • Official vendor ATS outputs (Workday, Greenhouse, etc.)
    • Roles that would require fabricating skills not on index.html

    Methodology

    For each job title, this board asks: If a resume were written only from facts already on index.html, optimized for that title’s typical ATS keywords, what match band is realistic? Densest families (L3 hosting, Linux/RHCE, MySQL/Percona HA, WP/Magento/Woo hosting, AWS/OpenStack hybrid, TAM/solutions language) can reach 95–100% and are featured first. Adjacent or thin families (Azure-primary, pure K8s lead, formal SecOps) score lower because index.html does not provide enough exclusive evidence without inventing experience.

    No artificial cap: when fact density supports near-complete keyword and experience overlap, scores can hit 100%. Real ATS systems still differ by employer keyword lists; these are editorial estimates from portfolio content, not Workday/Greenhouse exports.

    Live panels may pull Cloudflare/DigitalOcean status JSON and GitHub public repo metadata (no API keys) for market context only. They do not change resume facts or scores. Cache: six hours; use Refresh signals for an immediate pull.
